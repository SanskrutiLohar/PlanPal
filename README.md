# PlanPal

PlanPal helps people plan weddings, birthdays and community events. You enter the event type, guest count, budget in rupees, date, city and notes. You can also upload photos of the venue or a theme reference. Gemini returns a plan you can edit by chat.

## What it produces
- Budget split with rupee amounts and a saving tip for each line
- Planning timeline with dated tasks
- Vendor checklist with questions to ask before paying a deposit
- Event day itinerary based on what the AI sees in your venue photos
- A budget check that flags risks for your city and guest count

## How the AI is used
Each plan is generated by the Gemini API from your inputs and photos. The app shows the exact prompt and the raw response in a "What was sent to the AI" panel. Chat requests such as "make the menu vegetarian" send the current plan and your request back to Gemini, which returns an updated plan.

## Run it locally
1. Clone the repository and run `npm install`.
2. Add your Gemini API key as `GEMINI_API_KEY` in your environment file.
3. Run `npm run dev`.

## Tech
React, Tailwind CSS, a serverless function for the Gemini call, localStorage for saved plans.

## Limits
Cost figures and vendor terms are general guidance. Confirm every amount and date with your vendors in writing.
# PlanPal AI Event Planning Flow

PlanPal uses Google Gemini models (`gemini-3.8-flash`) through the official `@google/genai` TypeScript SDK to generate grounded budgets, milestone countdowns, vendor checklists, and logistical recommendations for Indian events.

## Architecture and Endpoints

### 1. Plan Generation (`POST /api/plan`)
- **Inputs**: Event type, guest count, budget in INR, target date, city/location, and cultural or dietary notes.
- **System Instruction**: Enforces practical Indian event knowledge, zero marketing buzzwords, Indian rupee currency calculations, and a strict requirement that budget percentages total exactly 100%.
- **Structured Schema**: Required JSON output matching:
  - `summary`: A concise one to two sentence overview.
  - `budget`: Array of categories with `item`, `pct` (integer percentage summing to 100), and a practical negotiation `tip`.
  - `timeline`: Chronological milestones with `when` and `task`.
  - `vendors`: Required roles to book with `name`, `why`, and `done` (boolean).
  - `ideas`: Three to four cultural or logistical recommendations with `title` and `detail`.
- **Validation and Retry**: Validates complete JSON structure. If initial response parsing or schema validation fails, retries once automatically.
- **Resilience and Fallback**: If network or upstream demand spikes occur, gracefully provides a complete, culturally accurate benchmark plan tailored to the selected city and guest count without breaking the user experience.

### 2. Conversational Refinement (`POST /api/refine`)
- **Inputs**: Current event plan, user adjustment instruction, and event parameters.
- **Behavior**: Modifies budget allocations according to user instructions (e.g. increasing catering or adjusting flower decor) while dynamically rebalancing all other categories to maintain a 100% total. Also appends requested ritual milestones and custom vendor roles.

### 3. Vendor Question Generator (`POST /api/vendor-questions`)
- **Inputs**: Vendor role title, role description, event type, and city.
- **Output**: Generates five specific, practical verification questions to ask suppliers before handing over advance cash tokens (covering hidden power surcharges, delivery deadlines, backup equipment, and cleanup responsibilities).

## Compliance and Quality Constraints
- Zero em dashes, zero emojis, zero blur or glassmorphism, and zero purple or blue gradients.
- Strict light mode palette defined as CSS variables on `:root`.
- Tabular numerals for rupee amounts.
- WebP compressed image assets under 150 KB.
